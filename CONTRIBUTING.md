# Contributing

Discuss substantial changes and their scope before implementation. Production implementation requires explicit owner approval. Read [repository instructions](AGENTS.md), the [PRD](PRD.md), and the applicable architecture and design documents. Keep changes focused and preserve existing workloads and unowned material.

For a submission, explain the problem and approach, link relevant decisions, and report commands, results, failures and skipped checks. Add tests appropriate to the change and update affected documentation. Do not conceal failing tests or include secrets, private identifiers, or material without permission. Identify third-party sources and licenses for added material.

Changes require review by the owner or designated maintainer; security-sensitive designs require independent security review. Approval and release gates are not claims that CI exists. Contribution licensing and provenance are subject to the pending scope review in [LICENSING](LICENSING.md); no copyright assignment or mandatory upstream submission is required.
