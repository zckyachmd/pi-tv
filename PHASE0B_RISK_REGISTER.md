# Phase 0B risk register

Updated 27 November 2026 from host-first evidence and the owner-reported Pi baseline. Risks are open; the prototype is not a production recommendation.

| ID | Risk | Evidence | State / next action |
|---|---|---|---|
| R-01 | Pi 4B 1 GB may not sustain compositor, browser and playback alongside existing services. | Only short idle owner-reported memory/CPU/thermal readings exist. macOS runtime behavior is not target evidence. | **Open, critical.** Owner approval for Phase 0C window, then staged playback/concurrency benchmarks with abort thresholds. |
| R-02 | Required providers may not authenticate or play under legitimate Pi browser/DRM distribution. | Host test loaded only public landing pages. Debian 12 ARM64 simulation found no Widevine package candidate. | **Open, critical.** Determine vendor-supported DRM path and test lawful reference accounts on target; do not bypass DRM. |
| R-03 | Product daemon compatibility with the actual target OS and runtime is unknown. | Full host-first daemon builds as AArch64 ELF in pinned Debian 12 ARM64; maximum required GLIBC symbol is 2.34. Actual Pi OS glibc/runtime execution remains untested. | **Open, high.** Compare against the approved target image's glibc and dependencies, then execute only in an authorized target test window. |
| R-04 | Package footprint or dependency selection could consume excessive disk space or disturb the shared host. | Chromium+Cage plan estimated about 709 MiB added installed size; PipeWire variant about 720 MiB. Plans were Debian 12, not the Pi's package sources. | **Open, high.** Review exact target repositories, disk headroom, dependency changes and service impact before requesting install approval. |
| R-05 | Mobile pairing and local transport may expose control to an impersonating device or LAN client. | Swift code compiles for iOS Simulator SDK; no app, QR scan/pairing server, wrong-certificate test, physical device, or end-to-end authentication was run. | **Open, critical.** Implement no production pairing until threat model, authenticated handshake, rotation/revocation, iOS permission UX and physical-device tests pass review. |
| R-06 | Browser control can become an unintended LAN entry point. | Host smoke verified loopback-only CDP. Prototype daemon uses loopback and local Origin checks, with no LAN auth. | **Open, high.** Keep development daemon local; before LAN access, define and validate auth, TLS identity, origin/CSRF defenses and port conflict behavior. |
| R-07 | Display, audio, hardware decode and thermal behavior may differ from host Chrome. | Pi connectors were owner-reported disconnected; no Pi desktop session, HDMI mode, hardware decode or playback run. | **Open, high.** Validate the actual non-root graphical session, HDMI/audio and decoder path on target. |
| R-08 | Resource measurements can be incomplete or distort a 1 GB playback test. | Target PSI is owner-reported unavailable; the sampler is prepared but not run. | **Open, medium.** Establish measured intervals, PSI fallback, sampling overhead and stop criteria before playback. |
| R-09 | Rustup tool selection can vary by shell and produce confusing builds. | Login shell uses pinned rustup; current non-login shell resolves Homebrew Rust first. | **Open, medium.** Use `scripts/phase0b/` wrappers or explicitly select rustup Cargo; verify shell selection before build commands. |
| R-10 | iOS Simulator service instability can block validation after a successful build. | Xcode app build passed, but `simctl install` timed out; simulator shutdown succeeded and no device identifier was retained. | **Open, medium.** Recheck simulator service/runtime, then repeat the install/launch smoke; physical iPhone validation remains required regardless. |

No risk is considered accepted by the current evidence. This register does not approve package installation, host changes, architecture choices, or product implementation.
