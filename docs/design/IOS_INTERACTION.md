# Native iOS interaction

Use native navigation stacks, sheets, safe areas, system typography and appearance. Support Dynamic Type including accessibility sizes by reflow and scrolling, not clipping. VoiceOver names, roles, values and actionable hints must describe controls and connection changes; do not announce every pointer delta. Respect Reduce Motion and system contrast settings. Every independent control has at least 44×44 pt hit area; verify D-pad sectors individually with VoiceOver and Switch Control. Haptics are optional, user-controllable and never the only feedback.

D-pad is primary: five separate labeled controls send discrete directional/select actions. Touchpad is an explicit mode, with bounded pointer movement, distinct scroll mode and adjustable sensitivity; provide accessible discrete alternatives to gestures. Back, Home and keyboard remain discoverable. A native keyboard sheet sends bounded text only after explicit user action; preserve editing focus, avoid logging or persisting sensitive text, and never represent delivery as provider acceptance. Media and volume controls reflect authenticated observed capabilities; unsupported or unknown is explained rather than silently assumed. Device management lists public labels and status, allows explicit selection and revocation through authorized flows, and explains recovery; never expose keys. Phone confirmation and recovery proof remain candidate ceremonies subject to independent security review. The board's circular arrangement and fixed frame are suggestions, not platform requirements.

Acceptance includes light/dark, large accessibility text, VoiceOver traversal and actions, 44 pt targets, Reduce Motion, disabled/unsupported controls, permission denial, reconnect and safe-area rotation on actual supported devices. Results are not yet measured.
