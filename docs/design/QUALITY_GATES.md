# Quality gates

Proposed implementation and release gates; no production CI is claimed. Design review requires the token validator to pass and component/state contracts to be reviewed against R-19 and the protocol. Each implementation PR must use semantic roles and run token reference, approved-pair contrast, mapping drift and literal-style checks; document reviewed exceptions for native system behavior. Generated CSS/Swift must be reproducible and checked against the canonical JSON.

Before release: test WCAG 2.2 AA applicable contrast and keyboard behavior, visible focus against all actual adjacent surfaces, and native VoiceOver, Dynamic Type, 44 pt targets, system appearance and Reduce Motion. Run keyboard focus graph tests at 1080p and 720p including dialogs, text input, errors and restoration. Test pseudolocalization, RTL and long text. Capture stable visual regressions for both TV sizes and iOS light/dark and accessibility text sizes; review diffs rather than accepting an arbitrary threshold. Include disabled, pressed, loading, error and connection states.

Record source, license and rights of every static asset; no unauthorized provider assets, remote fonts or launcher runtime image downloads. No heavy decorative rendering, perpetual animation, blur, glow or unnecessary UI dependencies. Initial launcher JavaScript must be ≤200 KiB compressed (also record raw size and compression method); budget is proposed under R-17, not a measurement. Measure frame timing, dropped frames, CPU, memory and input response on target during navigation and playback; use [benchmarks](../architecture/BENCHMARKS.md) for workload and acceptance rather than inventing an unmeasured performance guarantee. Reduced motion removes nonessential transitions. Owner review is required for deviations and threshold changes.
