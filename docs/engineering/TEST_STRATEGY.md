# Test strategy — planning contract

Proposed; no runtime results. The [PRD](../../PRD.md) defines requirements, [benchmarks](../architecture/BENCHMARKS.md) owns numeric candidates, [backlog](../planning/IMPLEMENTATION_BACKLOG.md) owns task order, and [release gates](RELEASE_GATES.md) owns release decisions.

| Layer | Required cases | Evidence / acceptance |
|---|---|---|
| Unit | Core fake ports; lifecycle generations, queue bounds, capability policy, errors, idempotency, held-key release; state projections | Deterministic tests, injected clock and failures; no external hardware needed |
| Contract | Versioned Rust/Swift fixtures, minimum negotiated payload, lengths, encoding, unknown required fields, fragments, duplicate/reorder, replay, error codes | Same semantic result across languages; fuzz malformed data and verify global/per-peer bounds; no execution of partial records |
| Security | Wrong identity, rogue central/peripheral, QR theft/racing/relay residual, expiry, downgrade, reconnect, revocation, owner vs control lease, hostile page/local process IPC, secrets/logging | Independent review of chosen protocol and libraries; negative tests and actual isolation evidence; no production credentials in experiments |
| Persistence | Crash before/after every ownership/recovery/revoke/reset commit; response loss; storage corruption, upgrade/migration, scope of erasure | Durable first owner never reverts to unowned; uncertain result reconciled; missing all proof fails closed; no profile wipe on normal restart |
| Adapter integration | Browser/compositor launch/stop and cleanup, input routing, local IPC, systemd supervision, BlueZ permission/flow control, network rollback | Explicit timeout/failure/unknown outcomes, no sandbox bypass, no global host mutation |
| UI | Canonical token validator, negative fixtures, mapping drift, actual contrast, spatial focus and modal restore, text input, capability gating, long labels/RTL, visual regressions | 720p/1080p screenshots; iOS light/dark, compact, Dynamic Type, VoiceOver, Reduce Motion, 44 pt targets; Ready only on authenticated current state |
| Physical BLE | Physical iPhone radio and target adapter, foreground connect/reconnect, permission denial, Wi-Fi/cellular off, contention, coexistence | Measured p50/p95/p99 and failures, explicit environment; simulator only fake UI transport |
| E2E appliance | Prepared media + TV + iPhone only, first boot, enroll, recovery kit, controller management, browser failure, HDMI reconnect, lost phone recovery, authorized reset | No USB/Bluetooth HID, GPIO, mandatory CEC, shared LAN or SSH as customer input; fatal OS/radio faults and lost all proof use maintenance; target evidence required |
| Media & performance | Lawful login/playback, input, codec/drops where observable, 30 switches, PSS, CPU, memory, swap, thermal, radio coexistence and existing services | Active benchmark method and measured scope; 24h integrated and 72h release soak only after short-run and authorization gates |
| Packaging | Install, upgrade, interrupted upgrade, remove vs purge, rollback, image first boot, unique identity, source delivery, signing verification | Real target/disposable image, preserved state unless explicit purge; no shared host shutdown; verified release rights |

## Candidate measurement refinements

See integration changes to BENCHMARKS.md. Candidate discrete admission/applied RTT p95 ≤100 ms is only for eligible discrete input at the documented adapter boundary; pointer p95 ≤150 ms is send-to-observed effect where measured. State query, lifecycle and pairing are separate classes; propose report distributions and establish thresholds after baseline, no arbitrary 100 ms completion requirement. Reconnect p95 ≤5 s to authenticated synchronized Ready. Propose cold boot ≤45 s to actionable launcher/enrollment and return-home ≤5 s to actionable launcher; record exact measurement boundaries and actual target conditions. At least 100 samples for high-frequency input/reconnect targets where practicable; disclose fewer samples, failure counts and uncertainty; never drop timeouts from acceptance accounting. Long-run metrics and hardware stop rules remain in BENCHMARKS.md. ZRAM is optional separately authorized comparison only; never change shared-host swap to obtain pass. 1080p60 optional stretch, not MVP floor. iOS 18 candidate minimum pending SDK, availability and actual physical-device evidence; no support claim.

## Test execution and evidence

Record task ID, commit/dirty state, command and exit status, tool/dependency versions, device/OS, environment, sample sizes and units, exact measurement endpoints, failures and skipped/unobservable cases, sanitized logs, raw evidence path, conclusion and next gate. Separate planned checks from executed checks. Evidence belongs in scoped `evidence/` paths without real QR secrets, peer identifiers, provider cookies, Wi-Fi credentials or typed text. Redact before committing, not after. Use PASS/FAIL/BLOCKED/NOT_RUN/NOT_OBSERVABLE/NOT_APPLICABLE with reasons. Unit/contract CI is not physical-device validation. Preserve existing historical evidence; no production changes until ratification. Independent review is required for security, and actual workload protection for shared host. Any abort triggers stop, evidence and review before retry; no automatic retry after a safety stop.
