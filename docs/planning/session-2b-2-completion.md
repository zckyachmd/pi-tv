## Authenticated host experiment — 2026-11-27

**PARTIAL: actual same-engine Rust–Swift interoperability passes; Session 2B.2 remains incomplete.** The owner accepted the SEC-11 ambiguity described in the [dependency checkpoint](../../evidence/phase2b/dependency-checkpoint.md#owner-disposition-of-sec-11--2026-11-27). The isolated [replacement workspace](../../prototypes/phase2b-tls/replacement/) uses the existing locked graph. The first-party Rust server uses rustls; the Swift client calls rustls-ffi through the documented C interface. Ephemeral synthetic fixtures are generated in temporary directories by the installed OpenSSL executable solely as a certificate-generation tool, with locally generated keys and controlled inputs. OpenSSL was not used as a TLS peer. No production credentials, hardware or CoreBluetooth were used.

Both endpoints completed full mutually authenticated TLS 1.3 handshakes, with webpki validation, client certificates required, hostname `pi-tv.test`, exact leaf DER pins and ALPN `pi-tv-experiment/1`, before sending application data. Two independent process runs exchanged framed synthetic plaintext in both directions with both messages queued before pumping, then exchanged and observed `close_notify`. This establishes Swift–C ABI integration and same-engine TLS interoperability, **not independent implementation interoperability**. The server refuses a pre-admission write and enters a terminal state; the Swift harness only writes after its own checks. TLS 1.3 and full handshake kind are checked on both ends; the server sends no TLS 1.3 tickets and does not allow early data. The client's per-run configuration is fresh; shared-cache resumption and early-data attacks have not been exhaustively tested.

The deterministic single-threaded in-memory harness uses at most one 4096-byte ciphertext chunk per direction and a separate logical receipt operation. Swift ciphertext writes are limited to 127 bytes to exercise partial writes. Its tested injected cases check bad receipt IDs, duplicate/reordered *chunk identifiers*, a missing middle chunk and a missing final close chunk. These are local model injections, not a full BLE adapter or proof against all loss, arbitrary delayed acknowledgements, reconnect generations or stale callbacks. A monotonic handshake deadline and bounded iteration counts cover these cases; delivery deadlines and backpressure behavior have not been fully validated under asynchronous traffic. The finite send-buffer limit is 16 KiB per TLS connection and does not establish a bound on all rustls, certificate, framework or process allocations.
