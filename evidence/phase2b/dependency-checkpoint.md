### FFI capability and open gates

The [documented C ABI and static linking guidance](https://github.com/rustls/rustls-ffi/blob/v0.15.7/README.md) provide a plausible Swift bridge, not proof of Swift import or ABI stability: upstream recommends static linking and does not guarantee ABI stability. The tagged source builds a `staticlib`; Rust documents ARM64 [iOS device and simulator targets](https://doc.rust-lang.org/rustc/platform-support/apple-ios.html), with deployment target configurable to 18. macOS ARM64 artifacts are documented upstream. None proves this complete ring/platform-verifier graph links or runs on iOS 18, simulator, or host; deployment-target metadata, native libraries and XCFramework slices must be checked after approval.

- Caller-owned read/write callbacks drive ciphertext without sockets, and `process_new_packets` advances TLS. Propagate partial I/O, `errno`, TLS errors and backpressure; don't treat an empty queue as EOF. Built-in webpki server and client verifiers, trust roots and client certificates provide a plausible mutual-authentication path; verify chain, DNS hostname, time and server/client EKU behavior with negative tests. Pin the authenticated leaf DER additionally before exposing plaintext. Do not replace verification with an accepting callback.
- Restrict versions to TLS 1.3, offer exactly one ALPN, then compare the negotiated bytes on **both** peers and reject absent/mismatched values before application data. TLS handshake completion can precede draining output. The server has a `set_send_tls13_tickets(0)` API; client configuration/session cache controls, defaults and early-data behavior need source and runtime proof. Use fresh configurations per connection where required, test handshake kind and replay, and do not assert fresh handshakes solely from a setting.
- `set_buffer_limit` covers unsent plaintext and TLS records only and defaults to unlimited; it is not a global handshake/certificate/inbound allocation cap. Bound outer queues, total received handshake bytes, deadlines and concurrent sessions independently and measure library allocation. `send_close_notify` queues output, which must be drained; verify the actual C ABI read/EOF mapping distinguishes authenticated close from truncation, including partial plaintext and disconnect during handshake. These are unresolved acceptance gates, not demonstrated guarantees.
- Each owned opaque pointer must be freed exactly once after all uses; prevent concurrent mutation and serialize connection calls. Peer certificate and ALPN buffers are borrowed only until the next connection mutation: copy while valid and never free them. I/O callback buffer pointers are borrowed for that call only; callback userdata must remain alive, counts must not exceed buffers, and callbacks must not reenter or throw across C. On cancellation stop new calls, quiesce callbacks, free connection and associated state once, and discard generations/queued plaintext. Verify config, verifier, certificate and callback-specific ownership individually against the tagged header. Upstream documents catching Rust unwinds on fallible calls as `RUSTLS_RESULT_PANIC`, but infallible calls may return default values; panic-abort, allocator abort, invalid pointers and foreign exceptions are not recoverable guarantees. Do not infer success from a default boolean or pointer. See [source](https://github.com/rustls/rustls-ffi/blob/v0.15.7/librustls/src/connection.rs) and [callback contract](https://github.com/rustls/rustls-ffi/blob/v0.15.7/librustls/src/io.rs).
