# Public repository and licensing governance

## License decision
Owner chose GPL 3.0 plus trademark policy. Proposed SPDX identifier `GPL-3.0-only` (owner to confirm only vs or-later). `LICENSE` in this bundle is an unmodified GNU GPL v3 text sourced from the system common-licenses copy; verify against https://www.gnu.org/licenses/gpl-3.0.txt and install at repo root after provenance review. Apply SPDX headers and package metadata only to project-owned material; preserve upstream notices and terms. Audit existing contributions, generated code, assets and dependencies; do not assume rights to third-party material. GPL permits commercial use, sale and redistribution. When conveying covered binaries or modifications, satisfy GPL obligations including corresponding source, notices and installation information when applicable. Private changes need not be published; no mandatory PR upstream. Encourage contributions via CONTRIBUTING, not additional license restrictions. Trademark policy cannot be a disguised noncommercial restriction. No proprietary DRM binary bundling without lawful rights; audit provider branding, fonts, icons and OS image redistribution separately. Never claim Raspberry Pi/vendor endorsement. Review name clearance before public brand release.

## iOS distribution gate
GPLv3 and App Store/TestFlight distribution terms may create additional restrictions or obligations; do not presume compatibility. Review current Apple agreements and applicable GPL clauses, including further restrictions, installation information and signing. Do not ship store binaries until counsel/qualified review confirms compliance or owner approves a lawful alternative. Possible options: distribute source for local build; owner-approved separate iOS license/exception only with all necessary copyright permissions and dependency compatibility; document exact component scope and avoid silently relicensing. No contributor agreement or copyright assignment without explicit owner approval. Use DCO/sign-off as candidate contribution provenance mechanism, not mandatory upstream contribution or license transfer.

## Required repo documents
README (scope, supported/unsupported matrix, quickstart, dev vs production, license); LICENSE; TRADEMARK_POLICY; CONTRIBUTING (review process, no secrets, test evidence, DCO decision); SECURITY (private reporting contact, support window, coordinated disclosure); THIRD_PARTY_NOTICES and SBOM; AGENTS.md (constraints, authority, no premature implementation, test expectations); docs index, PRD, architecture, ADRs, threat model, protocol spec, design system, performance and ops docs. Use SECURITY contact placeholder until owner supplies private channel. No fabricated support guarantees.

## Engineering policy
Protect main; planning PR and review before merge; no direct pushes unless explicitly authorized. Small reviewable changes, CI required, lockfiles, reproducible pinned builders; avoid non-login PATH ambiguity. Enforce rustfmt/clippy, tests, no unsafe in pure core/protocol, audited native boundary; TS strict/lint and Swift concurrency review. Dependency admission: active maintenance, security history, licensing compatibility, ARM64 builds, footprint, native dependencies, alternatives and rollback. `cargo-deny`/audit and ecosystem equivalents, SBOM, signed release, security update policy; tests and evidence before upgrade. No unnecessary dependencies, scaffolding or over-abstraction. Never alter tests to mask failures. Production code must not import prototypes. Add doc/ADR changes in same PR as changes. Secrets and user identifiers excluded from logs, evidence, git history; scan before publication. License gates cover source and distributed artifacts, not just Cargo metadata.
