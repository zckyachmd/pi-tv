Pi: authorized SSH/read-only capability review, storage/backup or spare microSD, 5V/3A supply/cooling, micro-HDMI to HDMI for display, local keyboard or recovery access, lawful provider accounts, supervised test window. Existing port 8080 is occupied; BLE removes LAN listener requirement; local loopback ports still conflict-check. Dedicated and shared profiles require separate results.

## Benchmarks and aborts (candidate thresholds)
Record raw sanitized output, exact versions, commit, durations, power/cooling, network, device model, profile, codec, resolution, content/account test description without secrets, instrumentation overhead, repetitions and limitations. Use PSS and cgroup accounting, MemAvailable, swap-in/out, CPU per core, thermal, dropped frames, application switching and service health. PSI absent on earlier host; report unavailable and fallback. Measure BLE commands at phone and target via correlated IDs; do not subtract unsynchronized clocks. Report roundtrip latency or calibrated one-way measurements, p50/p95/p99, loss, reconnect and UI actual response. Candidate idle 5 min, each playback scenario >=15 min x3, switching >=30 cycles, 24h soak and 72h release test. Preserve original benchmark protocol and reconcile. Abort on any existing service health degradation/OOM, new throttling, persistent MemAvailable <100 MiB (proposed 10s), sustained swap/I/O stall or browser runaway; stop only project processes and record. Never restart unrelated services to pass a test. Thresholds need owner confirmation before running on shared host.
